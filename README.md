# Backend CS Knowledge Base

Python 웹 백엔드 개발에 필요한 CS 지식을 대화, 실험, 프로젝트 경험과 연결해 축적하는 개인 지식 저장소다.

이 저장소는 완성된 글을 모으는 곳이 아니다. 질문에서 시작해 노트를 계속 고치고 연결하면서 **내가 설명하고 설계에 사용할 수 있는 지식**으로 만드는 곳이다.

## 시작점

- 전체 지식 지도: [[백엔드 지식 지도]]
- 노트를 추가하고 관리하는 기준: [[Knowledge Base 운영 지침]]
- 아직 정리하지 않은 질문: [[Inbox]]
- 최근 공부 기록: [[Learning Log]]
- 복습할 내용: [[Review Queue]]
- 책과 문서: [[Reading List]]

## 공부 흐름

1. 궁금한 내용이나 프로젝트에서 만난 문제를 [[Inbox]]에 적는다.
2. 대화를 통해 질문의 범위와 선행 개념을 확인한다.
3. 하나의 개념을 하나의 `notes/` 노트로 정리한다.
4. 관련 개념과의 **관계가 드러나게** 링크한다.
5. 필요하면 `labs/`에서 직접 재현한다.
6. 실제 설계 문제는 `cases/`에 기록한다.
7. 관련 MOC와 [[Review Queue]]를 갱신한다.
8. 공부한 날에는 [[Learning Log]]에 한 줄을 남긴다.

## 운영 원칙

구체적인 생성, 분리, 병합, 중복 관리 기준은 [[Knowledge Base 운영 지침]]을 따른다.

- **질문은 자유롭게, 결과는 주제별로 정리한다.**
- 대화 전문을 저장하지 않고, 검증된 이해와 남은 질문을 저장한다.
- 하나의 개념 노트는 가능하면 하나의 중심 질문만 다룬다.
- 링크를 걸 때는 두 노트가 어떤 관계인지 함께 적는다.
- 폴더보다 링크와 MOC를 사용해 여러 관점으로 지식을 찾는다.
- 모르는 내용과 추측은 확정된 사실처럼 기록하지 않는다.
- 개념은 가능하면 공식 문서, 신뢰할 만한 책, 직접 실험으로 검증한다.
- Git으로 관리할 경우 변경 이력은 Git에 맡기고 노트 안에 긴 수정 기록은 남기지 않는다.

## 대화할 때 사용할 수 있는 표현

특별한 명령어는 필요 없지만 다음처럼 말하면 작업 의도를 빠르게 구분할 수 있다.

- `정리해줘`: 지금까지 확인한 내용을 개념 노트에 반영
- `연결해줘`: 관련 노트와 프로젝트 사례를 찾아 관계 추가
- `실험해보자`: 작은 재현 코드나 테스트 작성
- `복습하자`: 저장된 노트를 기반으로 질문과 피드백 진행
- `현황 보여줘`: MOC, 학습 기록, 미해결 질문을 기준으로 다음 주제 제안

## 디렉터리

```text
inbox/      아직 분류하거나 해결하지 않은 질문
maps/       MOC(Map of Content), 지식의 진입점
notes/      하나의 개념을 다루는 원자적 노트
cases/      실제 프로젝트 문제와 설계 결정
labs/       개념을 검증하는 재현 실험
reviews/    복습 질문과 이해도 점검
resources/  책, 공식 문서, 강의 등의 목록
logs/       날짜별 학습 기록
templates/  새 노트를 만들 때 사용하는 양식
```
